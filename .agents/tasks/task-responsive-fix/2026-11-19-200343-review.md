# Responsive fix: remove zoom-simulation CSS and per-page scale wrappers

The site was previously using an `html` font-size staircase (ranging from 81.25% to 90%) to simulate browser zoom site-wide, plus per-page `.page-scale-80` and `.faq-scene-root` wrappers to push specific pages further down. This change removes all three mechanisms and restores the browser's 16px base, so the layout reads correctly at 100% zoom rather than requiring the user to zoom out. The approach is correct: CSS-level zoom simulation is the right thing to remove, and the TSX call-sites are cleaned up in the same set of commits.

**Watch for:** The `.acr-heading` clamp reduction (confirmed applied). CoinScene wrapper style (confirmed clean). `HeroSection` `w-full` addition (confirmed). No unrelated files changed.

**Verdict**: APPROVED

## High-level view

FEAT-001 strips the `html` block down to `scroll-behavior: smooth; font-size: 100%` and removes the `@media` staircase, `.page-scale-80`, and `.faq-scene-root` blocks entirely. The `.acr-heading` clamp is reduced from `68px` to `52px` max to prevent the About coin-reveal heading from blowing up at the restored 16px base — confirmed at line 404 of `index.css`.

FEAT-002 removes the className wrapper and inline scale from every TSX call-site. `BurnLiquidity`'s root `<div>` (line 336) has no class at all. `CoinScene`'s wrapper style (line 88) contains only `width`, `height`, `perspective`, and `perspectiveOrigin` — no `transform` or `transformOrigin`. `Tokenomics`, `Whitepaper`, and `FaqScene3D` are equally clean. `HeroSection`'s hero content div includes `w-full` as required.

The only files touched are the six source files in scope plus the FEAT-002 task JSON. Build passed twice (FEAT-001 and FEAT-002 each ran `npm run build`) with zero TypeScript errors and 21 Vite chunks. Pre-existing `sRGBEncoding` deprecation warnings in unrelated scene components are not part of this change.
